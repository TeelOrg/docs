The Teel API uses a **secret API key** sent as a bearer token on every request. Your server holds the key in env vars or a vault and presents it on every call.

```bash
curl https://api.teel.finance/recipients \
  -H "Authorization: Bearer sk_live_a3f2x9k7m4q8…"
```

## Key format

```
sk_<env>_<43 url-safe base64 chars>
```

| Prefix     | Environment | Base URL                            |
| ---------- | ----------- | ----------------------------------- |
| `sk_live_` | Production  | `https://api.teel.finance`          |
| `sk_test_` | Sandbox     | `https://api.teel.finance/sandbox`  |

<Note>
  Sandbox provider APIs don't move real funds — use `sk_test_…` keys against `api.teel.finance/sandbox` for end-to-end integration testing before switching to production credentials.
</Note>

The fixed `sk_` prefix is recognized by GitHub secret scanning, GitGuardian, and TruffleHog — if you accidentally commit a key, you'll get a leak notification. The visible `live` vs `test` distinction prevents the "prod creds in Slack" failure mode.

<Warning>
  Use each key only against its matching base URL. A key sent to the wrong environment is rejected with `403 ENV_SCOPE_MISMATCH` — `sk_live_…` belongs on `api.teel.finance`, `sk_test_…` on `api.teel.finance/sandbox`.
</Warning>

## Issuing a key

Create keys yourself in the Teel dashboard, once your business has completed onboarding:

1. Pick the environment with the **Sandbox** / **Production** switch in the dashboard header. A key created in Sandbox is an `sk_test_…` key; one created in Production is an `sk_live_…` key.
2. Open **Settings** → **API Keys** and click **Create API Key**.
3. Enter a **Label** that identifies where the key will be used, then create it.
4. Copy the key from the **Your New API Key** dialog and save it to your secret manager.

The plaintext key is shown **exactly once**. Teel stores only a hash of the key plus its first characters for identification, so it cannot be retrieved later. Create one key per service so you can revoke one without touching the others.

## Scopes

Each key carries a set of scopes. A key created from **API Keys** holds every scope in the table below.

The sandbox key you claim from the dashboard's one-time **Your sandbox API key** dialog holds `quotes:read`, `recipients:read`, `recipients:write`, `payouts:write`, `collections:read`, `collections:write` and `settlements:write`. It has no `payouts:read`, `webhooks:read` or `webhooks:write`; create a key from **API Keys** when you need those.

| Scope | What it allows |
| --- | --- |
| `quotes:read` | Fetch quotes (`/quotes/*`) |
| `payouts:write` | Execute payouts (`POST /rfq/execute`, `POST /rfq/execute-batch`, `POST /rfq/confirm-escrow-deposit`) and upload payout documents (`POST /payouts/document`) |
| `payouts:read` | List / fetch your own payouts |
| `recipients:write` | Create / update / delete recipients |
| `recipients:read` | List / fetch recipients |
| `webhooks:write` | Create / update / delete webhook subscriptions |
| `webhooks:read` | List / fetch webhook subscriptions and deliveries |
| `collections:read` | Read payment links, buyers, balances, receiving accounts, deposits and settlements; preview a settlement; subscribe to `collections.*` webhook events |
| `collections:write` | Create / void payment links; create / update / delete buyers |
| `settlements:write` | Upload a settlement invoice and create settlements (moves money) |

Manage webhook subscriptions through the API with the `webhooks:read` / `webhooks:write` scopes, or on the dashboard's **Settings** → **Webhooks** page. See the [Webhooks guide](/guides/webhooks).

## Rotation

To roll a key yourself:

1. Create a new key from **Settings** → **API Keys**.
2. Deploy it to your services.
3. **Revoke** the old key.

The old key stops working as soon as it is revoked, so finish step 2 first.

If you need both keys to work for a while, ask **support@teel.finance** to rotate the key instead. Support issues the new key alongside the existing one and keeps the previous key working for **7 days**. After that window, the old key returns `401`.

## Revocation

Revoke a key from **Settings** → **API Keys**: click **Revoke** on its row and confirm. You can also ask **support@teel.finance** to revoke it. A revoked key can keep working for up to 60 seconds while Teel's servers refresh; after that, every request with it returns `401`.

During incident response, revoke rather than rotate through support, because a support rotation keeps the old key working for 7 days.

## What happens if a key is compromised

1. **Blast radius is bounded by the key's scopes** — a key with `quotes:read` only cannot create payouts. Keys created from **API Keys** hold every scope, so keep one key per service and never reuse a production key in CI.
2. **Teel only custodies funds via escrow + smart wallets.** A captured key cannot drain a wallet — it can only place actions the holder of the key could place anyway, all of which are audited and rate-limited.
3. **Revoke first, investigate second.** Revoke the key, create a new one, and redeploy.

## Storage

- **Server-side only.** Never embed a `sk_live_…` key in a mobile app, browser bundle, or any artifact a partner of yours can read. Use a backend you control.
- **One secret per environment.** Mirror the key into your env-vars / vault under names like `TEEL_API_KEY`. Don't share a key across staging and production.
- **CI secret scanning.** Configure your CI to fail on `sk_live_` / `sk_test_` substrings in commits. Most CI providers have built-in detectors for this prefix shape.

## Error responses

| Status | Meaning |
| --- | --- |
| `401 Unauthorized` | Missing / malformed `Authorization` header, or the key is unknown / revoked |
| `403 Forbidden` | Key is valid but lacks the scope the endpoint requires (e.g. you called `POST /rfq/execute` with a `quotes:read`-only key), or the key was sent to the wrong environment host |
| `429 Too Many Requests` | Per-key rate limit exceeded — back off per the `Retry-After` header |

## Rate limiting

Per-key rate limits apply. Each response carries:

```http
X-RateLimit-Limit: 60
X-RateLimit-Remaining: 47
X-RateLimit-Reset: 1700001234
```

On a `429`, also: `Retry-After: <seconds>`. Wait at least that long before the next request.

Specific limits per endpoint family + the per-key default are documented in the [Errors & retries](/errors) guide.

## Dashboard authentication

The Teel dashboard is a separate, browser-only session and is **not** the API authentication path. Partner integrations should always use the `sk_` API key pattern above — dashboard sessions are not accepted on `api.teel.finance` or `api.teel.finance/sandbox`.

If you build an internal tool that needs to act on behalf of multiple Teel accounts, create one `sk_` key in each account rather than reusing your own dashboard session.
