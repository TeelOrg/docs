# Teel partner API docs — authoring guide

This repo is the source of **docs.teel.finance**: partner-facing documentation for the Teel API, built with [Mintlify](https://mintlify.com). Navigation lives in `docs.json`; pages are `.mdx` with YAML frontmatter.

## Where to edit

- **Author here, in `TeelOrg/mintlify-docs`.** `TeelOrg/docs` is an automatic mirror. Never edit it; changes there are overwritten.
- `teel-postman-collection.json` is regenerated by the `regen-postman-collection.yml` workflow in `TeelOrg/teel-backend` whenever the served OpenAPI spec changes. It opens a PR here. Don't hand-edit the collection.
- Internal files (`AGENTS.md`, `API-REFERENCE-DRIFT.md`, `.claude/`) are excluded from the site by `.mintignore` / Mintlify defaults.

## Sources of truth

Every claim in a page must be grounded in the backend, `TeelOrg/teel-backend` on `main`. Where sources disagree, **code wins**; record the disagreement in `API-REFERENCE-DRIFT.md`.

`PO` = `go-apps/backend/payments-orchestrator`.

| What | Where |
| --- | --- |
| Routes, scopes, rate-limit family, idempotency, `denyPartner` | `PO/cmd/main.go` (route chains: `scope → rate limiter → [entitlement] → [idempotency] → handler`) |
| Rate-limit families | `PO/internal/middleware/partner_rate_limit.go` |
| Scope and auth errors | `PO/internal/middleware/partner_auth.go` |
| Response shapes (partner allowlists) | `PO/internal/rest/partner_*_dto.go`, e.g. `partner_collections_dto.go`; JSON tags are the wire names |
| Request shapes and models | `go-apps/backend/shared/models/*.go` |
| Handlers, status codes, error codes | `PO/internal/rest/*_controller.go`; codes in `PO/internal/rest/api_errors.go` |
| Served OpenAPI spec | `PO/internal/rest/openapi/openapi.yaml` (served at `/openapi.json` and `/openapi.yaml`) |
| Design specs (context only, not authority) | `docs/superpowers/specs/` |
| Webhook event types and payloads | `go-apps/backend/shared/models/webhook.go`, `PO/internal/services/webhooks/subscriptions.go`, `PO/internal/rest/partner_collections_webhooks.go` |

## Page template (API reference)

One page per route. Follow `api-reference/payouts/*`, `api-reference/recipients/*` and `api-reference/collections/*`:

1. Frontmatter: `title` (sentence case), `api: METHOD /api/<path>` with `{param}` placeholders, `description`.
2. One or two sentences on what the route does, then an `<Info>` line naming the **scope** and **rate limit** (and entitlement, if any).
3. Sections, in this order, skipping any that don't apply (never leave one empty):
   `## Headers` → `## Path parameters` → `## Query parameters` → `## Request body` → `## Response` → `## Errors`.
4. `<ParamField>` for every input. Path params need an explicit `<ParamField path="…">`; the `api:` line alone does not render them.
5. `<ResponseField>` for every DTO field, with `<Expandable>` for nested objects. A JSON example alone is not documentation.
6. Examples fenced as ```` ```json 200 ```` (or the real status) inside `<ResponseExample>`.
7. Document `Idempotency-Key` wherever it is accepted or required: 8–255 `[A-Za-z0-9_-]`, the 24h replay window, `409 IDEMPOTENCY_KEY_REUSED` / `IDEMPOTENCY_REQUEST_IN_FLIGHT`.
8. `## Errors` as a `Status | Code | When` table, using codes from the spec's error enum.

Shared field lists live in `snippets/` and are imported, e.g. `import PaymentLinkFields from '/snippets/collections/payment-link-fields.mdx';`.

Guides live in `guides/`, concepts and state diagrams in `concepts.mdx` (Mermaid `stateDiagram-v2`, built from the real status enums).

## Rules

- **Casing**: exactly the struct JSON tags. The partner API is camelCase; a few legacy query params stay snake_case (`subscription_id`, `user_payment_method_id`).
- **No provider names.** Never name a banking, payments or liquidity provider in prose or examples. Use `provider_a` / `provider_b` if one is needed. Public protocol names (for example CCTP) are fine.
- **No internal references**: Jira keys, internal repo paths, runbooks, AWS resource IDs, internal hostnames.
- **Hosts**: production `https://api.teel.finance`; sandbox `https://api.teel.finance/sandbox` (WebSocket `wss://api.teel.finance/sandbox/ws`). `api-sandbox.teel.finance` has no DNS record; don't use it.
- **Known gaps go in `API-REFERENCE-DRIFT.md`, not on public pages.** Partner pages state current behaviour neutrally ("not yet …"), never internal bug narration.
- Every new page goes into `docs.json`. An unlisted page is an orphan.
- Style: second person, active voice, sentence-case headings, one idea per sentence.

## Before opening a PR

```bash
npx mint broken-links   # must be clean
npx mint dev            # spot-check the pages you touched on :3000
```

Then run the `docs-reviewer` checklist in `.claude/agents/docs-reviewer.md` against your diff and fix every Critical and Important finding. PRs target `main`; request `sohzhong` as reviewer.
