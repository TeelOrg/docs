---
title: Add a recipient payment method
api: POST /api/recipients/{id}/payment-methods
description: Add one bank account or wallet to an existing recipient.
---

Teel validates the payment method against the recipient's details, saves it, then registers it with each payout route. Call [`GET /recipients/requirements`](/api-reference/recipients/requirements) first for the fields each rail needs.

<Info>**Scope** `recipients:write` · rate limit `default` (60/min, burst 20)</Info>

## Headers

<ParamField header="Authorization" type="string" required>
  API key.
</ParamField>

<ParamField header="X-Teel-Entity-Id" type="string">
  Only needed when the key's owner belongs to more than one business. The UUID of the business this request acts for. Without it, such a key gets `400 ENTITY_REQUIRED`.
</ParamField>

<ParamField header="Idempotency-Key" type="string">
  Optional. 8–255 characters of `[A-Za-z0-9_-]`. The same key and body within 24 hours replays the original response. The same key with a different body returns `409 IDEMPOTENCY_KEY_REUSED`. A retry while the first request is still running returns `409 IDEMPOTENCY_REQUEST_IN_FLIGHT` with `Retry-After`.
</ParamField>

## Path parameters

<ParamField path="id" type="string" required>
  Recipient UUID.
</ParamField>

## Request body

Send only the fields the chosen `rail` needs.

<ParamField body="type" type="string" required>`"bank"` or `"wallet"`.</ParamField>
<ParamField body="currency" type="string" required>
  ISO 4217 code (bank) or token symbol (wallet) this payment method settles in. It selects the corridor and is never inferred from the recipient's country.
</ParamField>
<ParamField body="rail" type="string">
  For `type: "bank"`, the payment rail, for example `ach`, `sepa`, `pix`, or `mobile_money`. Defaults to `bank_transfer` when omitted. For `type: "wallet"`, the network the address is on, for example `polygon`: a `wallet.chains[].code` from [`GET /config/coverage`](/api-reference/config/coverage).
</ParamField>

## Response

`201` with the payment method when setup completed for every payout route. `207` when it was saved but its setup did not complete. A `207` body wraps the payment method and never says which route failed or why:

<ResponseField name="paymentMethod" type="object">`207` only. The saved payment method, with the fields below.</ResponseField>
<ResponseField name="provisioningError" type="string">`207` only. Present when setup failed. Display text that may change; branch on `retryable`, never on this text.</ResponseField>
<ResponseField name="retryable" type="boolean">`207` only. Set with `provisioningError`. `true` when every failure was temporary, so trying again shortly may complete setup. `false` means retrying will not help; contact support.</ResponseField>
<ResponseField name="provisioningWarning" type="string">`207` only. Present without `provisioningError` when the payment method was registered but some of its details could not be registered yet. Display text; try again shortly.</ResponseField>

### Errors

| Status | `code` | When |
|---|---|---|
| `400` | `INVALID_PARAMETER` | `id` is not a UUID. |
| `400` | `INVALID_JSON` | The body is not valid JSON. |
| `400` | `INVALID_REQUEST` | `currency` is missing, or the rail is not supported for the currency. |
| `400` | `VALIDATION_FAILED` | The payment method fails the recipient schema. `details.violations` lists each field. |
| `400` | `IDEMPOTENCY_KEY_INVALID` | `Idempotency-Key` is malformed. |
| `400` | `ENTITY_REQUIRED` | The key's owner belongs to more than one business and `X-Teel-Entity-Id` is missing. |
| `401` | `UNAUTHORIZED` | Missing or invalid key. |
| `403` | `INSUFFICIENT_SCOPE` | Key lacks `recipients:write`. |
| `404` | `RECIPIENT_NOT_FOUND` | The recipient does not exist or is not yours. Both answer the same. |
| `409` | `CONFLICT` | The recipient is your own Teel-held account (`isSelf`), which Teel manages. |
| `409` | `IDEMPOTENCY_KEY_REUSED` / `IDEMPOTENCY_REQUEST_IN_FLIGHT` | Idempotency conflict. For in-flight, wait for `Retry-After`. |
| `422` | `ADDRESS_SCREENING_BLOCKED` | The wallet address failed compliance screening. Nothing was saved. |
| `422` | `ADDRESS_SCREENING_UNDER_REVIEW` | The wallet address is under compliance review. Nothing was saved. |
| `429` | `RATE_LIMITED` | Per-key rate limit exhausted. Wait for `Retry-After`. |
| `503` | `ADDRESS_SCREENING_UNAVAILABLE` | Screening is temporarily unavailable. Nothing was saved; retry. |
