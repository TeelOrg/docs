title: Webhooks Overview
description: Receive real-time updates for transaction and account status changes
---

Teel sends real-time updates whenever events occur on your account (payout created, status changed, collections activity). Teel POSTs HMAC-signed events to a URL you register. See [Subscriptions](/api-reference/webhooks/subscriptions/list) and [Deliveries](/api-reference/webhooks/deliveries/list) for the management endpoints, and the [Webhooks guide](/guides/webhooks) for the verifier samples and retry rules. You can also manage subscriptions in the dashboard under **Settings** → **Webhooks**.

## Event types

Every event is delivered as the envelope `{ "type", "createdAt", "data" }`. These are the event types you can subscribe to:

| Event | When it fires | Extra scope to subscribe |
|---|---|---|
| `payout.created` | A payout was created | — |
| `payout.status.updated` | A payout's step or status changed | — |
| `collections.payment_link.paid` | A payment link reached `paid` | `collections:read` |
| `collections.deposit.received` | A deposit into a receiving account was credited | `collections:read` |
| `collections.offramp.status.updated` | A settlement changed status | `collections:read` |

Subscribing to a `collections.*` event with a key that lacks `collections:read` returns `403 INSUFFICIENT_SCOPE`. See the [Webhooks guide](/guides/webhooks) for payload shapes, including the [collections events](/guides/webhooks#collections-events).

## Collections event payloads

Each collections event's `data` is the same object the matching `GET` returns.

<ResponseField name="collections.payment_link.paid" type="object">
  `type`, `createdAt` (ISO 8601), and `data`: a payment link. Same fields as [Get payment link](/api-reference/collections/payment-links/get#response).
</ResponseField>

<ResponseField name="collections.deposit.received" type="object">
  `type`, `createdAt` (ISO 8601), and `data`: a deposit. Same fields as [Get deposit](/api-reference/collections/deposits/get#response).

</ResponseField>

## Responding to webhooks

Return a `2xx` response within 10 seconds to acknowledge receipt. Non-2xx responses (or timeouts) trigger automatic retries with exponential backoff. Make your handler idempotent — Teel may deliver the same event more than once during partial outages.
