---
title: Replay delivery
api: POST /api/webhooks/deliveries/{id}/replay
description: Enqueue a fresh delivery from the same source row
---

Enqueues a fresh delivery with the same payload + subscription. Worker picks it up within ~2 s; new delivery gets its own `Teel-Delivery-Id`.

Use this for:

- Debugging your verifier — drop a row, fix the bug, replay, watch it land.
- Recovering from a long outage on your side — walk the `permanently_failed` deliveries and replay them once your endpoint is healthy.

<Info>**Scope** `webhooks:write` · rate limit `default` (60/min, burst 20), plus 5 replays per minute per account (burst 5)</Info>

## Headers

<ParamField header="Authorization" type="string" required>
  API key.
</ParamField>

## Path parameters

<ParamField path="id" type="string" required>
  Source delivery UUID.
</ParamField>

## Response

<ResponseField name="id" type="string">
  UUID of the new delivery row.
</ResponseField>

<ResponseField name="subscriptionId" type="string">
  Inherited from the source delivery.
</ResponseField>

<ResponseField name="userId" type="string">
  UUID of the user that owns the subscription.
</ResponseField>

<ResponseField name="eventType" type="string">
  Inherited from the source delivery.
</ResponseField>

<ResponseField name="payload" type="object">
  Inherited from the source delivery: the JSON envelope that will be POSTed.
</ResponseField>

<ResponseField name="status" type="string">
  Always `pending` on a freshly enqueued replay.
</ResponseField>

<ResponseField name="attemptCount" type="integer">
  Always `0` — this is a brand-new delivery row, not a retry of the source.
</ResponseField>

<ResponseField name="nextAttemptAt" type="string">
  ISO 8601 timestamp of the first attempt (≈ now).
</ResponseField>

<ResponseField name="createdAt" type="string">
  ISO 8601 timestamp.
</ResponseField>

The remaining fields of a delivery (`lastResponseCode`, `lastResponseBody`, `lastError`, `deliveredAt`) are omitted until the first attempt; see [List deliveries](/api-reference/webhooks/deliveries/list).

## Errors

| Status | Code | When |
| --- | --- | --- |
| `400` | `INVALID_PARAMETER` | `id` is not a UUID. |
| `401` | `UNAUTHORIZED` | Missing or invalid key. |
| `403` | `INSUFFICIENT_SCOPE` | Key lacks `webhooks:write`. |
| `404` | `WEBHOOK_DELIVERY_NOT_FOUND` | The delivery does not exist or is not yours. |
| `429` | `RATE_LIMITED` | Rate limit hit. Wait for `Retry-After`. |
| `429` | — | The per-account replay limit (5 per minute) was hit. The body is `{"success": false, "error": "rate limit exceeded"}` with no `code`; wait for `Retry-After`. |
