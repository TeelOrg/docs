---
title: Execute a batch of payouts
api: POST /api/rfq/execute-batch
description: Submit N payouts that share a source currency, in one call.
---

Batched [`POST /rfq/execute`](/api-reference/payouts/execute). Rows share `fromCurrency` and the funding source. The call answers `202` as soon as the batch is recorded. Each row's rate is locked afterwards, so every row in the response is `pending`.

Use the returned `batchId` to follow the batch:

1. Poll [`GET /jobs/{jobId}`](/api-reference/jobs/get) with `batchId` as the `jobId`. It reports each row's verdict (`accepted` or `failed`), the locked rates, and `collectionId`. Stop on `terminal: true`.
2. Read the funding collection, and its deposit instructions, from [`GET /payouts/batch/{batchId}/collection`](/api-reference/payouts/batch-collection).
3. Follow each recipient's offramp order with [`GET /payouts/batch/{batchId}/rows`](/api-reference/payouts/batch-rows).

<Info>**Scope** `payouts:write` · rate limit `payouts_write` (30/min, burst 10) · requires payouts to be enabled for your business</Info>

## Headers

<ParamField header="Authorization" type="string" required>
  API key.
</ParamField>

<ParamField header="Idempotency-Key" type="string">
  Optional, recommended. 8–255 characters from `[A-Za-z0-9_-]`. Within 24 hours, a retry with the same key replays the original `202` instead of submitting the batch again. The same key with a different body returns `409 IDEMPOTENCY_KEY_REUSED`; a retry while the first request is still running returns `409 IDEMPOTENCY_REQUEST_IN_FLIGHT`. Per-row dedup uses `items[].idempotency_key`.
</ParamField>

## Request body

<Info>
  **Batch is exact-output by design.** Each row's `targetAmount` is what the recipient receives; the engine sizes the source spend. `items[].amount` is informational, except from the collections wallet (see below).
</Info>

<ParamField body="fromCurrency" type="string" required>Shared source currency.</ParamField>
<ParamField body="onrampProtocol" type="string" required>Opaque onramp route token from a quote. Every row shares the same onramp route. Required even when it is unused.</ParamField>
<ParamField body="userPaymentMethodId" type="string" required>UUID of the shared funding source.</ParamField>
<ParamField body="railPreference" type="string">
  How each row's payout rail is chosen. `best_rate` (default): each row locks on its cheapest route across rails. `fastest`: each row whose corridor has more than one rail is put on the fastest rail it can use. Any other value returns `400 INVALID_PARAMETER`.
</ParamField>
<ParamField body="walletAddresses" type="object" deprecated>Ignored.</ParamField>
<ParamField body="items" type="object[]" required>
  Non-empty array of payouts, at most 49.
  <Expandable title="items[]">
    <ParamField body="toCurrency" type="string" required>Destination currency.</ParamField>
    <ParamField body="targetAmount" type="number" required>Destination amount the recipient receives. Must be `> 0`.</ParamField>
    <ParamField body="recipientId" type="string" required>Recipient UUID.</ParamField>
    <ParamField body="recipientPaymentMethodId" type="string">Recipient payment method UUID.</ParamField>
    <ParamField body="amount" type="number">Informational source amount; `targetAmount` drives quoting. Required from the collections wallet.</ParamField>
    <ParamField body="offrampProvider" type="string">The offramp the row is locked through. A row it cannot price fails rather than locking on another offramp.</ParamField>
    <ParamField body="routeProtocol" type="string">Per-row opaque route token.</ParamField>
    <ParamField body="paymentPurpose" type="string">Per-row classification.</ParamField>
    <ParamField body="purposeDescription" type="string">Per-row free-text description of the purpose.</ParamField>
    <ParamField body="reference" type="string">Per-row free-text reference.</ParamField>
    <ParamField body="idempotency_key" type="string">Per-row dedup key. A row whose key matches a live payout from an earlier batch is reported `duplicate` on the job poll and is not charged again.</ParamField>
    <ParamField body="supportingDocumentFileId" type="string">The `fileId` from [`POST /payouts/document`](/api-reference/payouts/upload-document), for a row whose route asks for a document. Sending `supportingDocumentKey` or `payoutRail` on a row returns `400 INVALID_PARAMETER`.</ParamField>
  </Expandable>
</ParamField>

### From the collections wallet

When `userPaymentMethodId` is your business's collections wallet, each row is sent as its own stablecoin payout from the wallet. There is no collection and no `/payouts/batch/{batchId}/rows` result: [`GET /jobs/{jobId}`](/api-reference/jobs/get) is the whole answer. Every row needs `supportingDocumentFileId` (else `422 SUPPORTING_DOCUMENT_REQUIRED`) and `amount`, the source its own quote showed (else `400 INVALID_PARAMETER`).

## Errors

These refuse the whole batch before anything is created.

| Status | Code | When |
|---|---|---|
| `400` | `INVALID_JSON` | Body malformed, or a required field is missing. |
| `400` | `INVALID_PARAMETER` | A UUID is malformed, `railPreference` is unknown, a row sends `payoutRail` or `supportingDocumentKey`, a `supportingDocumentFileId` is not a document you uploaded, or a collections-wallet row has no `amount`. |
| `400` | none | More than 49 items. The body is `{"success": false, "error": "…"}`. |
| `401` | `UNAUTHORIZED` | Missing or invalid key. |
| `403` | `INSUFFICIENT_SCOPE` | Key lacks `payouts:write`. |
| `403` | `PAYOUTS_NOT_ENABLED` | Payouts are not enabled for your business. |
| `403` | `APPROVAL_REQUIRED` | Your business approves payouts before they execute, so this route cannot commit one in a single call. |
| `403` | `FORBIDDEN` | A currency is outside your business's payouts scope. |
| `404` | `RECIPIENT_NOT_FOUND` / `PAYMENT_METHOD_NOT_FOUND` | A recipient or payment method does not exist or is not yours. |
| `409` | `IDEMPOTENCY_KEY_REUSED` / `IDEMPOTENCY_REQUEST_IN_FLIGHT` | Idempotency conflict. |
| `422` | `DIRECT_BANK_BATCH_UNSUPPORTED` | The funding route pays directly from your bank account. Create those payouts one at a time with [`POST /rfq/execute`](/api-reference/payouts/execute). |
| `422` | `OWNER_HELD_WALLET_BATCH_UNSUPPORTED` | The funding wallet is held by your business's owners, so a teammate signs each send. Send this batch from the dashboard. |
| `422` | `SUPPORTING_DOCUMENT_REQUIRED` | A collections-wallet row has no `supportingDocumentFileId`. |
| `422` | `PAYMENT_METHOD_UNAVAILABLE` | The funding source could not be found. |
| `422` | `COLLECTIONS_WALLET_SOURCE_NOT_SUPPORTED` | The funding source is a collections wallet that cannot fund payouts. |
| `422` | `FUNDING_RAIL_UNSUPPORTED` | The funding source is a held balance, which a batch cannot fund. |
| `429` | `RATE_LIMITED` | Per-key rate limit. Wait for `Retry-After`. |
| `502` / `503` | `DOWNSTREAM_UNAVAILABLE` | The payout engine, or the funding source's details, could not be reached. Nothing was created. Retry with the same `Idempotency-Key`. |
| `503` | none | The batch could not be started; nothing was created. The body is `{"success": false, "error": "…"}`, with `"retryable": true` when a retry can succeed. Retry with the same `Idempotency-Key`. |

### After the `202`

A failure after the response is reported on [`GET /jobs/{jobId}`](/api-reference/jobs/get), never as an HTTP error here:

- A row that fails to lock is `failed` with its `errorCode`; the other rows proceed. Resend a `retryable: true` row with the same `idempotency_key`.
- A recipient the route's payout partner has not cleared fails the whole batch. The job ends `failed` with `failureCode` `RECIPIENT_VERIFICATION_PENDING` or `RECIPIENT_VERIFICATION_FAILED`, and `error` names the recipient.
