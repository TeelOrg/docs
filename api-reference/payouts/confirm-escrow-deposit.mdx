---
title: Confirm escrow deposit
api: POST /api/rfq/confirm-escrow-deposit
description: Manual fallback when auto-detection misses your on-chain deposit.
---

S2F payouts auto-detect deposits to `escrowAddress` via on-chain log polling (~10 s interval, runs for as long as the quote lock is alive). If your transfer lands but auto-detect misses it, post the tx hash here to register the deposit manually. Idempotent on duplicate `(quoteId, txHash)`.

Scope: `payouts:write`. Rate-limited.

## Headers

<ParamField header="Authorization" type="string" required>
  `Bearer sk_test_…` / `Bearer sk_live_…`.
</ParamField>

<ParamField header="Idempotency-Key" type="string">Optional.</ParamField>

## Request body

<ParamField body="quoteId" type="string" required>UUID of the original quote. Must be in `awaiting_escrow_deposit`.</ParamField>
<ParamField body="txHash" type="string" required>`0x`-prefixed transaction hash. Teel verifies the on-chain amount, address, and chain match.</ParamField>

## Response

<ResponseField name="success" type="boolean">Always `true` on success. No other fields — fetch detail via [`GET /rfq/status/{quoteId}`](/api-reference/payouts/status).</ResponseField>

<ResponseExample>
```json 200
{ "success": true }
```
</ResponseExample>

## Errors

| Status | When |
|---|---|
| `400` | `txHash` malformed, on-chain tx doesn't match (wrong amount/address/chain), or not yet confirmed. |
| `401` | Missing or invalid key. |
| `404` | Quote not in `awaiting_escrow_deposit` — auto-detect already credited the deposit, or it's not an S2F payout. |

## When not to call this

Don't call in the first few minutes — auto-detect is actively watching. Only fall back here if the quote is still `awaiting_escrow_deposit` minutes after your tx confirmed on-chain.
