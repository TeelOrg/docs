---
title: List payment purposes
api: GET /api/payouts/payment-purposes
description: The values you can send as a payout's paymentPurpose.
---

The list is the same for every route. It is static: fetch it once per session and cache it. Responses carry `Cache-Control: public, max-age=3600`.

Send one `value` as `paymentPurpose` when you execute a payout. An unrecognised value is passed through but will not match any route's purpose mapping, so the payout is filed under that route's default purpose. Always send a value from this list. `other` also requires a `purposeDescription` of 10–255 characters.

<Info>**Scope** `payouts:read` · rate limit `default` (60/min, burst 20)</Info>

## Headers

<ParamField header="Authorization" type="string" required>
  API key.
</ParamField>

## Response

<ResponseField name="purposes" type="object[]">

    <ResponseField name="value" type="string">Value to send as `paymentPurpose`.</ResponseField>

  </Expandable>
</ResponseField>

## Errors

| Status | Code | When |
|---|---|---|
| `401` | `UNAUTHORIZED` | Missing or invalid key. |
| `403` | `INSUFFICIENT_SCOPE` | Key lacks `payouts:read`. |
| `429` | `RATE_LIMITED` | Per-key rate limit. Wait for `Retry-After`. |
