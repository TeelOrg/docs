<Info>**Scope** `payouts:read` · rate limit `default` (60/min, burst 20)</Info>

## Headers

<ParamField header="Authorization" type="string" required>
  API key.
</ParamField>

## Path parameters

<ParamField path="id" type="string" required>
  Payout UUID: `transactionId` from [`GET /rfq/status/{quoteId}`](/api-reference/payouts/status), or `payoutId` from [`POST /rfq/execute`](/api-reference/payouts/execute) when it is set.
</ParamField>

## Query parameters

<ParamField query="detailed" type="boolean">
  `true` adds `recipientEmail`, `recipientBusinessName` and `recipientCountry` to the payout. That view leaves out `recipientId`, `recipientName`, both payment-method ids, `purposeDescription`, `idempotencyKey`, the refund fields, `receiptEmailedAt`, `payoutRailLabel` and both arrival times.
</ParamField>

## Response

The payout object. Fields marked as present only in some cases are omitted otherwise.

## Errors

| Status | Code | When |
| --- | --- | --- |
| `400` | `INVALID_PARAMETER` | `id` is not a UUID. |
| `401` | `UNAUTHORIZED` | Missing or invalid key. |
| `403` | `INSUFFICIENT_SCOPE` | Key lacks `payouts:read`. |
| `404` | `NOT_FOUND` | The payout does not exist, belongs to another business, or has not been released yet. All three answer the same body. |
| `429` | `RATE_LIMITED` | Per-key rate limit. Wait for `Retry-After`. |
