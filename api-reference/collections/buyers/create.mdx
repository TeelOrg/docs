Creates a buyer and returns it with `201`.

<Warning>
  To issue **stablecoin** links to this buyer, set `depositAddress: true`. That mints the buyer's own receiving address, which every stablecoin link to them is paid to. The API has no separate call to mint one later. If the response comes back without a `receivingAddress`, minting failed; contact support or create the buyer again.
</Warning>

<Info>**Scope** `collections:write` · rate limit `collections_write` (30/min, burst 10)</Info>

## Headers

<Headers />

<ParamField header="Idempotency-Key" type="string">
  Optional. 8–255 characters of `[A-Za-z0-9_-]`. The same key and body within 24 hours replays the original response with `Idempotency-Replayed: true`. The same key with a different body returns `409 IDEMPOTENCY_KEY_REUSED`. A retry while the first request is still running returns `409 IDEMPOTENCY_REQUEST_IN_FLIGHT` with `Retry-After`.
</ParamField>

## Request body

<ParamField body="name" type="string" required>
  Buyer name. Can't be blank.
</ParamField>

<ParamField body="email" type="string">
  Where invoices issued to this buyer are emailed.
</ParamField>

<ParamField body="depositAddress" type="boolean" default="false">
  Mint the buyer's on-chain receiving address now. Needed before you can issue them a stablecoin link.
</ParamField>

<ParamField body="entityType" type="string">
  `individual` or `business`.
</ParamField>

<ParamField body="country" type="string">
  ISO 3166-1 alpha-2, for example `SG`.
</ParamField>

<ParamField body="wallets" type="object[]">
  Wallets this buyer sends from, recorded for attribution. A wallet already recorded on another of your buyers returns `409 ALREADY_EXISTS`.
  <Expandable title="wallets[]">
    <ParamField body="address" type="string" required>Wallet address. EVM addresses are stored lowercased.</ParamField>
    <ParamField body="chain" type="string" required>Network of the address. A Tron address must say `tron`; an EVM address can't.</ParamField>
    <ParamField body="hostedType" type="string">`hosted`, `unhosted` or `unknown`.</ParamField>
    <ParamField body="screeningStatus" type="string">`unscreened`, `pending`, `cleared` or `blocked`.</ParamField>
  </Expandable>
</ParamField>

<ParamField body="screeningStatus" type="string">
  Your own screening record for the buyer: `unscreened`, `pending`, `cleared` or `blocked`. Stored but not returned on reads.
</ParamField>

<ParamField body="tier" type="string">
  Your own label, up to 20 characters. Stored but not returned on reads.
</ParamField>

<ParamField body="perPaymentCap" type="string">
  Your own note of a per-payment cap, as a decimal string (at most 13 digits before the point and 6 after). Stored but not enforced or returned on reads.
</ParamField>

<ParamField body="notes" type="string">
  Free-text notes. Stored but not returned on reads.
</ParamField>

## Errors

| Status | Code | When |
| --- | --- | --- |
| `400` | `INVALID_REQUEST` | Body malformed, `name` blank, or a field fails validation (bad `entityType`, `country`, `screeningStatus`, `perPaymentCap` or wallet). |
| `400` | `IDEMPOTENCY_KEY_INVALID` | `Idempotency-Key` is malformed. |
| `400` | `ENTITY_REQUIRED` | The key's owner belongs to more than one business and `X-Teel-Entity-Id` is missing. |
| `401` | `UNAUTHORIZED` | Missing or invalid key. |
| `403` | `INSUFFICIENT_SCOPE` | Key lacks `collections:write`. |
| `409` | `ALREADY_EXISTS` | A wallet in `wallets` is already recorded on another of your buyers. |
| `409` | `IDEMPOTENCY_KEY_REUSED` / `IDEMPOTENCY_REQUEST_IN_FLIGHT` | Idempotency conflict. For in-flight, wait for `Retry-After`. |
| `429` | `RATE_LIMITED` | `collections_write` budget exhausted. Wait for `Retry-After`. |
